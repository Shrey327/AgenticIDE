A proposed global kernel-default setter was rejected by automatic approval review; that setter was not executed, and no runtime kernel default was changed.

All new host-mutating operations use the internal desktop service boundary. MCP retains explicit scopes and allowlists; UI-only document, sharing, local speech setup and sandbox network preparation operations are not generic externally callable tools.

## Remaining scope and release gates

These limitations remain visible because local automation cannot establish their outcomes:

- Physical microphone/language/acoustic acceptance, prolonged concurrent voice load and actual local chat-model quality. PSTN/SIP routing and managed call operations are outside the selected local desktop workflow.
- Signed/notarized distribution and clean install/upgrade/rollback; there is no usable signing identity on this machine. Linux/Windows native UI/audio/install and GPU hardware acceptance require those platforms/devices. Windows does not yet provide POSIX-equivalent descendant cleanup.
- Docker remains a shared-kernel isolation boundary; required Apple VM isolation is available on the documented host/runtime. Staged storage has a monitored budget, not a hard disk quota. Hostile guest-kernel escape testing, remote microVM adapters and a full third-party-extension offline network audit are not established.
- Reviewed custom Python Gymnasium factories are implemented for supported flat spaces and run with host privileges. Image/Dict policies, robotics, distributed/GPU learning and language-model alignment remain separate work.
- Semantic/hybrid memory/RAG retrieval and optional reranker protocol support are implemented. Remote/multi-repository memory connectors, automatic truth verification and transactional collection-wide reindexing remain. Real-model synthesis/reranker quality and representative multilingual corpora require evaluation.
- Online annotation operations, a visual durable business-workflow runtime, formal independently versioned adapter SDK, distributed serving/training, immutable large-artifact registry and real hosted-service integrations retain their original audit gaps. Shareable local artifacts address the confirmed product target; hosted RBAC/accounts are not added.

The repository is a developer preview with substantially expanded tested local workflows. These remaining items are not marked complete or hidden behind optional feature flags. See [implementation status](implementation.md) for the broader platform and operational limits.
