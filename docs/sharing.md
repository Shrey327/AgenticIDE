# Shareable local project bundles

Project sharing creates a portable ZIP from files you explicitly select. It does not start a hosted server or upload data. Choose **Share project artifacts**, select source files or enter additional workspace-relative paths for notes, evaluation datasets, policy artifacts or model files, then **Preview export**. Inspect the exact paths, byte counts, SHA-256 hashes and sanitized project configuration before **Export reviewed ZIP**. Changes after preview invalidate the review hash.

No files or model weights are preselected. The source chooser omits common credential paths, symlinks, generated `.aiide` state and common model-weight formats. A manual selection can include model/policy artifacts up to 64 MB each; bundles allow at most 2,000 files, 200 MB expanded and 100 MB compressed. Filename filtering does not identify every secret embedded in source code, datasets or notes. Users must review the selected contents. Voice recordings and generated evaluation outputs require explicit selection as ordinary files; internal `.aiide` databases/credentials are never copied.

The generated `.aiide/project.yaml` contains no host-specific interpreter, commands, model/service connections or credentials. Content capture is disabled. The user sets up the environment and model connections after import. Share the ZIP with your file manager; the IDE does not transmit it.

To import, copy the ZIP into the current workspace, enter its relative path and a new project folder name, then **Inspect bundle**. The preview verifies the archive, per-file SHA-256 integrity and safe project manifest. **Import as new project** creates the reviewed snapshot in a new folder. An archive changed after review is rejected. Existing folders are never replaced, including in concurrent-import races. Extraction occurs in private staging and uses an atomic no-overwrite directory rename on macOS/Linux/Windows. Other platforms reject import if that atomic primitive is unavailable. Failed imports remove only their temporary staging directory.

Import never executes project code, installs packages, enables telemetry content capture or switches projects automatically. Use the separate open action when ready, review the source, and decide whether to trust and execute it. Source code, notes and agent instructions in a bundle remain untrusted input.

New or opened projects create `.aiide/.gitignore` only when it is absent. It excludes runtime databases, drafts, histories, credentials, task records and RAG namespace identity while allowing `.aiide/project.yaml` and the ignore file itself. Existing user ignore rules are preserved. Git does not ignore files already tracked: Home reports detected tracked private paths, and the user must review the index/history and untrack them manually while retaining local copies. The IDE never rewrites the index or root ignore policy. This default is not content-based secret detection; explicitly shared source, notes and exports still need review.

The importer rejects absolute/parent/backslash paths, NUL names, symbolic links and special files, encrypted entries, duplicate/case-conflicting names, Windows-reserved names, quota violations, mismatched hashes, incomplete provenance and unsafe project settings. Central-directory size/count is bounded before ZIP object allocation; ZIP64 and multi-volume archives are unsupported. ZIP content is streamed with expansion limits rather than using `extractall`. The bundle manifest (`aiide-bundle.json`) describes file hashes; imported `.aiide/bundle-source.json` retains the source archive hash. These are integrity/provenance records, not a signature establishing who authored the project.

Operations are `bundles.files`, `bundles.preview({files})`, `bundles.export({files,reviewHash})`, `bundles.inspect({file})` and `bundles.import({file,name,reviewHash})`. Archive paths are workspace-relative. The implementation uses Python's standard-library ZIP support and adds no package dependency. Validation includes real ZIP round-trips, source/archive review conflicts, protected/symlink paths, no-overwrite import, and malicious archive paths, links, collisions, quotas, provenance and commands.

Closing a workspace aborts and awaits active bundle helpers. A closed bundle service refuses new operations; cancelled imports cannot continue publishing a project after shutdown. Cancellation removes the helper process group. Forced cancellation or an OS crash can leave a private `.aiide/bundle-imports/` staging directory or `.aiide/bundles/*.tmp.zip` file for manual inspection/removal; it never publishes that unfinished project or executes its contents.
